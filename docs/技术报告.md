## 1. 概述

墨页是一个**在本机运行**的文档 → Markdown 转换工作台。浏览器页面只负责提交任务和观察进度，所有转换都在本机常驻服务里完成；关掉页面，任务照跑。

- 代码规模：约 1.4 万行（前端 `app/page.tsx` 3083 行、服务入口 `local-ocr-server.mjs` 2001 行）
- 使用情况（`data/moye.db`）：

  | 模式 | 状态 | 份数 | 页数 |
  |---|---|---:|---:|
  | ai | done | 253 | 6676 |
  | ai | failed | 1 | — |
  | fast | done | 92 | 92 |
  | fast | failed | 2 | — |

## 2. 功能清单

### 2.1 主功能：转成 Markdown（进队列、进 Library）

**支持的输入**

| 类型 | 扩展名 | 预处理 |
|---|---|---|
| PDF | `.pdf` | — |
| Office | `.ppt` `.pptx` `.doc` `.docx` | LibreOffice 转 PDF（`server/office2pdf.mjs`，按文件头魔数校验；每次转换时现找 soffice，没装会明说） |
| 图片 | `.png` `.jpg` `.jpeg` `.webp` `.bmp` `.gif` `.tif` `.tiff` `.heic` `.heif` | 包成 PDF（`server/image2pdf.mjs`，Pillow；HEIC 走 macOS `sips`） |

**转换模式**

| 模式 | 实现 | 并发（份） | 特点 |
|---|---|---:|---|
| `fast` 快速 | pdfjs 读文字层 + 排版还原 | 4 | 几乎零资源，只适合电子版；可中途取消 |
| `balanced` 本机 | Surya OCR → HTML → Markdown | 1 | 完全离线，吃满 CPU/GPU |
| `math` | 同走 Surya 分支 | 1 | 服务端接受，**前端未暴露**（`app/page.tsx:108` 的 `visibleModes`） |
| `ai` | 逐页渲染成图 → 视觉模型；文字层作提示与兜底 | 1（`MOYE_AI_JOB_CONCURRENCY`） | 质量最高；真正并发上限由全局 aiGate 决定 |

**AI 模式的关键机制**

- **五家 provider**：Gemini、OpenRouter、Kimi、Qwen（阿里百炼）、本机 Ollama。可多渠道同时启用，按权重分流。
- **自适应节流**（`server/pacer.mjs`）：每个渠道一条 AIMD 车道——成功慢慢提速、超时砍半，活总派给空位最多的车道；某家挂了流量自动流向别家。
- **三层兜底**：换供应商（OpenRouter 底层供应商白名单）→ 换模型（fallback 模型链）→ 回退 PDF 文字层。401/402 这类账号错误整条链立刻停，不再挨家试。
- **重试规则**（`server/fetch-timeout.mjs` 的 `postWithRetries`）：只重试 5xx、网络错误和有限次数的 429；其他 4xx 直接报错并带上游状态码。Gemini Key 只在明确的 401/403/API_KEY_INVALID 时拉黑，保存设置即解除。
- **逐页校验**（`validateAiPage`）：检查公式数、选项数等是否与初稿对得上。
- **`noText` 路径**：模型可声明「本页无可提取文字」，记为成功并写入「需复核」清单，而不是记成失败。
- **逐页 checkpoint**（`data/jobs/<id>/pages.jsonl`）：服务重启后续跑，已完成页直接复用。
- **只重跑回退页**：`POST /api/library/<id>/refine {only:"fallback"}`，成功页原样保留，不重复花钱。

### 2.2 Library（资料库）

- 每份结果由模型一次生成 `tags + ai_title + ai_one_line + filename_meaningful`（`generateCardMeta`），支持「补标签」回填老记录。
- 下载命名：`名字 转换日期.md`，原文件名有意义就用原名，否则用 AI 标题；下载 PDF、导出报告 JSON 也用同一规则。
- 整包下载 ZIP（手写最小 ZIP 打包器 `server/zip.mjs`）。Library 和整包下载都不再有 500 条上限。
- 结果页四个 tab，「渲染」tab 支持 LaTeX。
- 每份显示费用（`jobs.cost_usd` 等列，是这份文档历次精校和打标签的累计）。模式选择处的「每页约多少钱」改用 `/api/usage` 里 purpose=refine 的平均值，不受重跑影响。

### 2.3 旁路转换（不进队列、不进 Library）

| 功能 | 入口 | 实现要点 |
|---|---|---|
| Markdown → PDF | 结果页「下载 PDF」/ 首页拖入 `.md` | marked + KaTeX → HTML → 自带 chrome-headless-shell 经 DevTools 协议 `Page.printToPDF`；版面对照 Obsidian 导出样式；大文档按标题切段（默认 300KB）分别打印、失败重试、pdf-lib 合并 |
| 多张图片 → 一份 PDF | 待转区有图片时的「合成一份 PDF」 | 像素不缩，JPEG/PNG 原字节 embed；其他格式经 Pillow 转换；按文件名自然序排页；分片上传防内存堆积；坏图跳过并经 `X-Moye-Skipped` 告知 |

### 2.4 统一面板

| 栏目 | 说明 |
|---|---|
| 回顾 | 按时段统计（高峰星期/时段、按日曲线、主题占比）+ 模型写中英叙事（默认 Gemini flash-lite）；后台预算、缓存、过期先给旧的再重算；补完标题标签后叙事也会更新 |
| 资料库 | Library 列表 |
| 用量 | 每次模型调用的 token 与费用（`data/usage.db`）；OpenRouter 用响应里的 `usage.cost`，Gemini 按价格表算，未知价格标「未计价」 |
| AI 精校设置 | provider / 模型 / Key（只回传打码版，`__KEEP__` 占位防误覆盖） |
| 环境 | 检测 Python 环境、Surya+llama-server、LibreOffice、自带浏览器、Ollama 及视觉模型、AI 服务；一键补装；Ollama 拉模型带字节级进度、自动测速选魔搭或官方源 |
| 关于 | — |

### 2.5 其他体验

- 预计剩余时间：`/api/speed` 按模式取最近 50 份每页秒数中位数；跑到一定进度后改用本份实时速度。

### 4.2 关键设计决策（均有实测依据）

1. **逐页转图而非直传 PDF**：同一份 4 页 PDF，逐页 14.1s vs 直传 29.5s，产出多 18%；逐页还能并行、逐页校验与回退。
2. **AI 模式默认一次只跑 1 份文档**：aiGate 是全局共享预算（按设置算：OpenRouter 默认五家 40 路，多渠道相加如 68 路），多份并跑只会摊薄，谁都交付不了。
3. **AI 模式不先跑 Surya**：用几乎零成本的文字层当提示，扫描件则为纯视觉识别。
4. **分组渲染（48 页）**：698 页整本一次渲染会产生 350MB base64 并超时；分组后峰值内存 3.9GB → 0.8GB。
5. **文字层放短命子进程**：pdfjs 解析大书占 3GB 且不释放。
6. **Ollama 只用 Instruct 版、走原生接口**：思考版模型在 JSON Schema 下输出为空；兼容层设不了 `num_ctx` 会静默截断；死循环时以 `presence_penalty` 重试，禁用 `repeat_penalty`（会破坏 `\\frac`）。
7. **PDF 打印走 `--remote-debugging-pipe` + 分段**：`--print-to-pdf` 在大文档上必崩；单次 >150 页渲染进程偶发崩溃。浏览器找不到这类重试也没用的错误不再白试 3 次。
8. **绝不静默吞错误**：所有失败路径留日志（`[AI失败]`、`[换供应商]`、`[换模型]`、`[模型熔断]`、`[补救]`）；前端的补标签、复制、下载、取消、搜索失败都会弹提示。
9. **8765 只接本机请求**（`server/request-guard.mjs`）：校验 Host 与 Origin，防 DNS rebinding 和任意网页对本机发 POST。
10. **参数错误回 400**：路由按 pathname 匹配（带查询串不再 404），用户输入问题由带 `httpStatus` 的错误回 400，不再一律 500。

### 4.3 部署与运行

- 两个 launchd agent：`com.kapozux.moye-ocr`（8765）、`com.kapozux.moye-web`（3000），KeepAlive。
- `npm run build` 后必须重启 web 服务，否则 JS chunk 哈希不一致导致白屏。
- 密钥只存 `settings.local.json`（0600，gitignore），页面只拿打码版。

## 5. 现状问题与建议

2026-10-12 按深度报告第 8 节的问题表修过一轮（详见 [`moye_deep_report.md`](moye_deep_report.md) 末尾「第二部分」）。原表里的「未提交」「无行为测试」两条已解决；`fast` 失败的 11 份已降到 2 份（都是 Office 转 PDF 超时）。

| # | 问题 | 建议 |
|---|---|---|
| 1 | `tesseract.js` 依赖与根目录 `eng.traineddata`、`chi_tra.traineddata` 无任何代码引用 | grep 确认后移除，减小安装体积 |
