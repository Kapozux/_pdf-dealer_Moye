# 墨页 UI 规范

改界面之前先读这一页。墨页主要是 AI 在改，没有规范的话，最常见的退化是「往结果页再加一个按钮」「再加一行 9px 的小字」。
这里的条目大多来自 2026-10 对照 Verbatim（`~/Documents/CODEelse/getAudio`）的那一轮改动，以及之后实测踩到的问题。

## 原则

1. **一个区域只有一个主按钮。** 结果页只有「下载 .md」是绿色实心的，复制挨着它，其余（下载 PDF、重新精校、导出报告）进「⋯」。新功能先想它属于哪个已有的按钮或菜单，而不是新开一个。
2. **做决定要看的信息不能是全页最小的字。** 字号下限 12px。唯一的例外是文件图标里装饰性的「PDF」小字（7px）。模式说明「多快 · 花不花钱 · 上不上传」以前是 9px，用户恰恰要靠它选模式。
3. **报错说人话，并给出下一步。** 类别和文案在 `page.tsx` 的 `errorCopy`，分类规则在 `lib/explain-error.mjs`（按库里真实出现过的报错定）。原始报错收进可展开的「原始报错」，**不要只放在悬停提示里**——触屏看不到，也复制不了。重跑也救不了的（额度、Key、模型）要明说，并给「打开设置」。
4. **每个界面、每一页都有地址。** `#/library`、`#/doc/<id>`、`#/batch/<id>`、`#/doc/<id>/p/<n>`（逐页核对的第 n 页）。新视图要能被分享、能被后退回来；同一份文档里前进后退不重新拉结果。
5. **开始之前就说清楚会发生什么。** 待转区显示页数、「已在资料库」、预计用时和花费；按钮上不写空泛的「开始」。
6. **标签说实话。** 不知道出处就说「本地初稿」，不冒充 Surya；结果为空就写「结果为空」，不写「已回退」。隐私胶囊同理（见 `page.tsx` 里那段注释）。

## 功能放哪

| 位置 | 放什么 | 不放什么 |
|---|---|---|
| 顶栏 | 进行中（一个任务直接跳，多个弹列表）、Library、外观、语言、设置、隐私胶囊 | 和某份文档有关的操作 |
| 首页 | 拖放区、模式、待转区（预检）、服务端进行中、最近转换 | 设置项 |
| 结果页头部 | 返回、复制、下载 .md（主）、「⋯」 | 第二个主按钮 |
| 回退汇总条 | 几页、为什么、哪些重跑也没用；逐页核对回退页、只重跑回退页、打开设置 | 和回退无关的提示 |
| 结果标签 | Markdown · 逐页核对 · 逐页质量 · AI 前后对照 · 原始 PDF | 新标签之前先问：能不能是已有标签里的一个视图 |
| Library 工具栏 | 搜索（文件名 / 标签 / 正文）、最多两个质量筛选（带数字，0 不显示）、整包下载 | 每个服务商一颗筛选（Verbatim 那样，手机上折成 5 行） |
| 统一面板（左侧栏目） | 回顾、资料库统计、用量、AI 精校设置、环境、关于 | 需要频繁点的东西 |

## 视觉

- **颜色一律走变量**（`app/globals.css` 顶部）。新颜色先找语义变量：`--ink` / `--ink-rgb`（文字、线条，配透明度用）、`--paper`、`--panel`、`--surface-rgb`（浮在纸上的半透明白面板）、`--green`（强调）/ `--green-fill`（绿底白字的按钮）、`--warm-rgb`（提醒 / 回退的暖棕）、`--mark`（搜索高亮）。`--c-<原色>-bg / -fg` 是从零散颜色收进来的，新代码别再加这种。
- **状态色**：绿 = 采用 / 通过；暖棕 = 建议检查；红（`.page-dot.bad`、回退汇总）= AI 失败 / 回退；灰 = 没有文字或没交给模型。
- **暗色**：跟随系统，顶栏可切（跟随系统 → 浅色 → 深色，存在 `localStorage.moye_theme`，`layout.tsx` 开页就设好 `<html data-theme>`）。暗色值写在 `globals.css` 的两段暗色块里（内容相同，一段给系统偏好，一段给手动切换），**改了一段要改另一段**。原图、PDF 预览保持白底。
- 圆角沿用现有：按钮 9px、卡片 12–14px、胶囊 999px。手机断点 700px（布局）和 560px（模式按钮上下排、顶栏只留圆标）。

## 文案

- 界面上的字都过 `t("中文")`，中文就是 key；**每加一个 key，`lib/i18n.ts` 的 `en` 表里要有英文**（下面清单里的检查脚本会抓漏掉的）。
- 服务端发来的原因、进度、报错走 `tServer()`，它按模式翻译常见的几十种。
- 语气：短句，先说结论再说原因，下一步用动词开头（「去设置检查这家服务的 Key」）。不用「请您」。

## 改完的检查清单

1. `npm run test:unit`、`npx tsc --noEmit`、`npm run lint` 都过。
2. 中文 key 都有英文：
   ```bash
   node --input-type=module -e 'import{readFile}from"node:fs/promises";const p=await readFile("app/page.tsx","utf8"),i=await readFile("lib/i18n.ts","utf8");const k=new Set([...i.matchAll(/\n  "((?:[^"\\]|\\.)*)":/g)].map(m=>m[1]));console.log([...new Set([...p.matchAll(/\bt\("((?:[^"\\]|\\.)*)"/g)].map(m=>m[1]))].filter(x=>!k.has(x)&&/[一-鿿]/.test(x)))'
   ```
3. `npm run build`，然后**必须**重启网页服务（CLAUDE.md 第二条），确认每个 chunk 都是 200。
4. 截图对照：三个宽度（1440 / 1000 / 390）× 浅色、深色，至少看改过的那个界面：
   ```bash
   node scripts/screenshot.mjs /tmp/after.png "http://localhost:3000/#/library" 390 844 dark
   ```
   用的是 `data/browser/` 里自带的无头浏览器，不会碰用户的 Chrome。
5. 键盘能用（Tab 到得了、Esc 关得掉弹层），弹层点外面会关。
